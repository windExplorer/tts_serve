## 1. 统一 HTTP 契约（保持不变）

新服务必须保持与原 `cosyvoice_api.py` 兼容，这样 AstrBot 插件不用改代码。

### `GET /`

健康检查，返回：

```json
{"sample_rate": 24000}
```

> 插件客户端首次合成会自动拉取该值并覆盖配置，避免音频变速。  
> Qwen3 的实际采样率由 `generate_voice_clone` 返回的 `sr` 决定，服务启动时先做一次极短生成获取。

### `GET /voices`

返回可用音色列表。`voices.json` 映射保持不变：

```json
{
  "音色名": {
    "prompt_wav": "文件名.wav",
    "prompt_text": "参考音频逐字对应的原文"
  }
}
```

### `POST /inference_zero_shot`

form 字段：

- `tts_text`：待合成文本
- `prompt_text`：参考文本
- `prompt_wav`：上传的参考音频（可选）
- `prompt_wav_path`：服务端本地路径/文件名（可选）

返回：`application/octet-stream`，**裸 int16 little-endian PCM**，采样率与 `GET /` 一致。

### `POST /inference_instruct2`

插件当前未使用，可先返回 501，或后续映射到 Qwen3 的指令控制能力。

后端抽象接口建议至少包含：

- `load()`

- `sample_rate()`
- `list_voices()`
- `unload()`（为 ComfyUI 轮班释放显存）

## 3. Qwen3-TTS-0.6B 部署步骤

### 3.1 环境

```bat
cd /d D:\AI\TTS_SERVE\tts_serve
uv venv --python 3.12 .venv-qwen3
.venv-qwen3\Scripts\activate
uv pip install -U soundfile fastapi uvicorn python-multipart modelscope
uv pip install -U qwen-tts
uv pip install --reinstall torch torchaudio --index-url https://download.pytorch.org/whl/cu130
```

先不要安装 `flash-attn`，用 `sdpa`。

> PyPI 默认拉的是 CPU 版 torch，必须最后用 PyTorch 官方 CUDA 源强制重装，否则 `device_map="cuda:0"` 会报 `Torch not compiled with CUDA enabled`。cu130 要求驱动 CUDA ≥ 13.0（本机驱动 13.5 可用）。

### 3.2 下载模型

国内推荐 ModelScope：

```bat
modelscope download --model Qwen/Qwen3-TTS-12Hz-0.6B-Base --local_dir .\models\Qwen3-TTS-12Hz-0.6B-Base
```

确认模型名是 **`-12Hz-0.6B-Base`**，不是 CustomVoice / VoiceDesign。

### 3.3 裸模型冒烟测试

在写服务适配层之前，先做一次最小验证：

```python
import torch
import soundfile as sf
from qwen_tts import Qwen3TTSModel

model = Qwen3TTSModel.from_pretrained(
    r".\models\Qwen3-TTS-12Hz-0.6B-Base",
    device_map="cuda:0",
    dtype=torch.bfloat16,
    attn_implementation="sdpa",
)

wavs, sr = model.generate_voice_clone(
    text="你好，这是一次测试。今天天气不错，我们出去走走吧。",
    language="Chinese",
    ref_audio=r".\voices\你的音色.wav",
    ref_text="参考音频里逐字对应的原文",
)

sf.write("test_qwen3.wav", wavs[0], sr)
print("sample_rate =", sr)
```

先听生成结果，确认：

- 音色是否像；
- 标点/停顿是否正常；
- 速度是否可接受。

### 3.4 服务适配层要点

在 `backends/qwen3.py` 中：

```python
model = Qwen3TTSModel.from_pretrained(
    local_model_dir,
    device_map="cuda:0",
    dtype=torch.bfloat16,
    attn_implementation="sdpa",
)

wavs, sr = model.generate_voice_clone(
    text=tts_text,
    language="Chinese",
    ref_audio=ref_wav_path,
    ref_text=prompt_text,
)

pcm = (wavs[0] * 32767).astype("<i2").tobytes()
return pcm, sr
```

注意：

- `language` 用 `"Chinese"`（官方示例用 `"English"`，中文按同命名风格传）。
- `ref_text` 必须是参考音频的**逐字原文**，不要加 `<|endofprompt|>`。
- Qwen3 不再有 CosyVoice3 的自动 instruct 注入问题。
- 启动时做一次极短 warmup 生成，拿到真实 `sr` 供 `GET /` 返回。
- 保留全局锁先串行，队列后续再做。

## 5. 切换与验证流程

### 5.1 配置切换

建议用环境变量或配置文件：

```bat
set MODEL_BACKEND=qwen3
```

或

```yaml
model_backend: qwen3   # qwen3 | cosyvoice3
```

### 5.2 插件侧配置

AstrBot 插件只需改 `base_url`：

- Qwen3 服务：`http://127.0.0.1:50001`
- CosyVoice3 服务：`http://127.0.0.1:50000`

建议两个服务先并存，方便 A/B 对比。

其他配置保持不变：

- `voices/` 映射不变；
- `prompt_text` 仍填逐字原文；
- `tts_concurrency` 先保持 1。

### 5.3 验收清单

- [ ] `GET /` 返回正确 `sample_rate`
- [ ] `GET /voices` 返回音色列表
- [ ] `/tts0 你好，这是一次测试。今天天气不错，我们出去走走吧。` 能出声
- [ ] Qwen3 服务端日志无 `<|endofprompt|> auto prepend`
- [ ] 标点/停顿比 CosyVoice3 更自然
- [ ] 同一段文字下，Qwen3 生成耗时可接受
- [ ] ComfyUI 轮班后，服务能重新加载模型并正常合成

### 5.4 对比方法

同一段文字分别走两个服务：

```text
/tts0 你好，这是一次测试。今天天气不错，我们出去走走吧。
```

重点对比：

- 停顿/连读；
- 克隆音色相似度；
- 日志耗时；
- `合成 i/N` 中的段数（Qwen3 侧也要关注分段）。

## 6. 已知坑与注意事项

1. **Windows `flash-attn`**：先用 `sdpa`，别在第一步卡住。
2. **模型路径**：避免中文、空格。
3. **`ref_text` 必须逐字对应**：这是克隆质量的关键。
4. **ComfyUI 轮班**：需要实现 `unload()` 或由队列调度确保显存释放。
5. **插件并发先保持 1**：队列/并发优化放到模型切换稳定之后。
6. **官方 Gradio demo 不兼容插件契约**：`qwen-tts-demo` 是 WebUI，不能直接当本项目 HTTP 服务用，需要自写适配层。
7. **AstrBot 插件打包流程**（后续若改插件）：先改 `metadata.yaml` 版本号 → `git add -A && git commit` → 再运行 `pack.py`。
8. **PyPI 的 torch 是 CPU 版**：按 3.1 用 `--reinstall` 从 PyTorch 官方 CUDA 源重装，否则 GPU 推理直接失败。
